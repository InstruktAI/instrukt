# T3 coordination

Use this route when the coordinating computer selects `runner.runtime: t3`.
Your role is to arrange one local configuration task per participating T3
environment and reconcile the results. Each local agent performs the
configuration workflow in [../SKILL.md](../SKILL.md) on its own computer.

## Discover the environment capabilities

Use the linked-environment discovery and task capabilities exposed by the
authenticated T3 connection. Their published descriptions supply current
arguments, target-environment selection, permission limits and completion
instructions. T3's **Outside agents** documentation describes environment MCP
access, sign-in and permission modes; `t3 -h` describes the host CLI and its
environment-linking surface. Host-local thread operations are described by
T3's published thread help.

Match participating computers to those linked environments and their registered
project paths. An instrukt machine ID identifies configuration placement;
a T3 environment ID addresses the runtime connection. Establish that mapping
from observations and report unresolved mappings before assigning writes.

For an unlinked, inaccessible or insufficiently permitted environment, report
the linking/access prerequisite and supply the local skill brief. Operator
access setup follows T3's published instructions and the connection's own
authentication flow.

## Assign local configuration

Send one task to each participating environment, including the coordinating
computer's local work. Address the target environment explicitly through the
available T3 capability. A host-local thread start executes on that host;
it does not target another environment. Follow the selected capability's
instructions for task placement, execution and completion.

Each brief gives the local agent:

- The agreed cluster facts and its computer's intended settings and module
  enablement, including its existing stable instrukt machine ID when known.
- Participating project identities and that environment's registered checkout
  paths, including ingress source homes where applicable.
- A readable copy or checkout location for the complete `instrukt-configure`
  skill directory. Include its text when no readable package location exists.
- Its assignment: perform **Converge and verify locally**, return the **Report
  the result** fields, and send outside-scope observations and prerequisites
  back to the coordinator.

Use the environment's existing project and permission settings. The task
configures and verifies that computer through instrukt's local commands.
Supply secret references; local agents resolve their own credentials.

## Reconcile completion

Follow T3's completion instructions and inspect each local result before
marking it verified. Dispatch success alone proves no configuration change or
infrastructure health. Compare ingress identity, logical cluster store and
project placement across reports; report differences for targeted local repair.

Keep successful results when another environment fails. Identify the unfinished
computer, its reported prerequisite and the local skill entry for continuing
there. A repeated configuration request reads existing settings and active task
state first, then continues or repairs the affected local work.
