# Docs — Spec

## What it is

The docs context owns documentation as the way agents are instructed: what a
snippet is, how its identity follows from where it lives, which structure makes
it valid, how pending material sits beside the current contract, and how an
agent discovers and reads snippets in phases. It answers `instrukt docs
validate`, `instrukt docs index` and `instrukt docs get`. Discovery and index
metadata come from the home (`~/.instrukt`); published bodies are read there,
while local bodies are read from the project paths their index entries carry,
including another project's indexed local file. Validation reads the invoking
repository's working tree. Docs never writes the home or decides what a project
publishes. Publication writes published files and the index and reads only its
own repository; reading a configured value is configuration's work.

## Canonical fields

### Ubiquitous language

**Snippet**
: A Markdown document under a repository's `docs/global/<domain>/` or
`docs/local/`, with frontmatter, an H1 ending in its type, and the H2 sections
its taxonomy requires (`general/spec/snippet-authoring-schema`).

**Half**
: The part of a repository a snippet lives in. The **published half**
(`docs/global/`) is copied into the home; the **local half** (`docs/local/`)
stays in the project, and only its index entries enter the home.

**Identity**
: A snippet's id, derived from its path and never authored:
`<domain>/<taxonomy>/<rest>` in the published half,
`local/projects/<slug>/<taxonomy>/<rest>` in the local half, where `<slug>` is
the `project` the repository declares in its `instrukt.yaml`.

**Taxonomy**
: The snippet's type, from its taxonomy directory: principle, concept, policy,
procedure, design, spec, adr. Order of listing follows this sequence.

**Domain**
: A published knowledge area (`general`, `sdlc`, …), owned by exactly one
publishing project.

**Required read**
: An `@` reference in a snippet's `## Required reads` section naming another
snippet, or a domain bundle, that must have been read before this one.

**Inline reference**
: An `@<path>.md` reference in a snippet body; rendered as an absolute path
when read.

**Fragment**
: A shared text body under `docs/global/snippets/`, inlined where an
`@include` directive names it. Not a snippet; never retrieved by id.

**Configured value**
: A `@config` directive in a snippet body naming a configuration path, resolved
in-process when the snippet is read, with the value placed where the directive
stood. The snippet format has no directive that runs a command.

**Baseline manifest**
: A domain's `baseline.md` (and `baseline-progressive.md`), or a project's
`docs/local/baseline.md`: a list of `@` references naming the snippets every
agent in that domain or project reads.

**Bundle**
: The generated, pre-resolved baseline of one published domain
(`~/.instrukt/docs/<domain>/bundle.md`). Generated by publication; a valid
required read; not a snippet.

**Third-party doc**
: Curated external documentation under `docs/third-party/`, indexed apart from
taxonomy snippets, never a required read.

**Pending snippet**
: A snippet carrying `delivered_by`: intended state not yet delivered.

**Companion**
: `<stem>.<slug>.md` beside a live snippet — the complete next version the
named todo delivers. An empty companion retires the snippet.

**Planned block**
: An in-body `planned:<slug>` (addition) or `planned-change:<slug>`
(replacement) block carrying a todo's pending change to a live snippet.

**Superseded by**
: The todo slugs with pending material for a live snippet, derived from its
companions and planned blocks; never authored.

**Lens**
: The view a read takes on pending material: the current contract by default,
or one todo's future with `--target <slug>`.

**Index entry**
: What the home records about one snippet: identity, type, domain, scope,
description, pending markers, owning project, and for a local snippet the
absolute path of its file in the project.

**Closure**
: One procedure together with its transitive required reads and the bundles
they name, read in one pass.

**Published commit**
: The commit of a project's canonical main that publication last published;
recorded by publication.

### Ownership boundary

- **Owns** — the snippet model (identity derivation, taxonomy, frontmatter
  fields and where each is allowed, sections, reference forms and placement,
  fragments, baseline manifests, third-party doc shape); structural validation
  and its findings; the pending-documentation model and the lens; phase-1
  listing, phase-2 reading, the read pipeline and configured values; the
  publication-behind warning on read.
- **Does not own** — copying snippets into the home, writing or patching the
  global and local indexes, generating bundles, compiling `AGENTS.md`
  entrypoints, recording the published commit (publication); the `project`
  slug and every configured value (configuration); whether a todo slug names an
  existing todo (work, when the `todos` module is on); deciding when publication
  runs (repository).
- **Published contracts** — `instrukt docs validate [paths] [--json]`; `instrukt docs fold <slug>`;
  `instrukt docs index [--domains] [--areas] [--baseline-only] [--third-party]
  [--target <slug>] [--project <slug>]`; `instrukt docs get <id…> [--closure]
  [--target <slug>]`; the snippet model as stated in
  `general/spec/snippet-authoring-schema`, which publication relies on to
  derive index entries.
- **Allowed dependencies** — publication (reads the home it writes and the
  published commit it records); configuration (the `project` slug, and the
  in-process resolution of `@config` paths); work (todo-slug
  existence through an interface core declares and the CLI wires only when
  `todos` is enabled); workflow (declared flavor roles through a core-declared
  lookup interface wired by the CLI when `todos` is enabled).
- **Implementation roots** — the docs module of the `instrukt-core` crate;
  its module layout is set by the architecture design.

### Aggregates

#### Snippet (aggregate)

- **Root:** Snippet.
- **Contains:** frontmatter, sections, required reads, inline references,
  directives (`@include`, `@config`), companions, planned blocks.
- **Invariants:**
  - Identity, type, domain and scope follow from the path and the project's
    declared slug; none is authored.
  - The H1 is the first content line and ends with `— <Type>` of its taxonomy.
  - `description` is present; a snippet without one is a validation finding,
    never silently dropped.
  - `@` references appear only under `## Required reads`, which is the first
    H2 when present.
  - A companion shares its parent's identity and never appears in a listing.
  - `delivered_by` is the only pending frontmatter field; pending material for
    a live snippet lives only in companions and planned blocks.
- **Identifier:** the derived identity.
- **Lifecycle:** authored in a repository; current once delivered (its
  `delivered_by`, companion or planned block is folded away by the delivering
  work); retired by an empty companion that the delivery deletes together with
  the parent.

#### Third-party doc (aggregate)

- **Root:** Third-party doc.
- **Invariants:** authors only `description`; its `## Sources` are web URLs or
  identifiers of a documentation service; never a required read.
- **Identifier:** derived from its path below the third-party root.
- **Lifecycle:** authored and curated in a repository; published with it.

### Domain events emitted

None. instrukt runs no daemon and emits no events from this context.

### Domain events consumed

None.

### Use cases (index of feature specs)

- **progressive-retrieval** — `docs/local/spec/feature/docs/progressive-retrieval.md` — an agent finds what to read, reads it with its required reads, and sees values computed in its own context.
- **snippet-validation** — `docs/local/spec/feature/docs/snippet-validation.md` — a developer learns which snippets break the snippet contract before committing.
- **pending-documentation** — `docs/local/spec/feature/docs/pending-documentation.md` — intended changes are written ahead of the build without misleading readers of the current contract.

### Governing designs and decisions (index)

- **`general/spec/snippet-authoring-schema`** — the snippet schema this context enforces.
- **`general/procedure/doc-snippet-authoring`** — how authors use the pending carriers this context reads.
- **`general/policy/context-retrieval`** — how agents are directed to use the three phases.

### Context map position

- **Publication** — customer / supplier. Publication supplies the home's
  published files, indexes and published commit. Docs supplies publication with
  snippet identity, validation, baseline and reference contracts. Local bodies
  come from indexed project paths; validation reads the invoking working tree.
- **Configuration** — customer / supplier. Configuration supplies the
  project's slug and resolves `@config` paths in-process through its `get`.
- **Repository** — no direct relationship; repository triggers publication.
- **Work** — customer / supplier: work supplies todo-slug existence when
  `todos` is enabled, through the core interface wired by the CLI.
- **Workflow** — customer / supplier: workflow supplies the flavor’s declared
  roles for validation through the core-declared lookup interface when todos is on.

- **Specs** — customer / supplier: docs supplies feature-spec use-case inventory
  and pending markers.
- **Runner** — customer / supplier: docs supplies procedures and their event
  subscriptions.

## Known caveats

- A snippet never decides what runs on a machine: `@config` resolves a
  configuration path in-process, and a leftover `@exec` is inert text and a
  validation finding.
- With no publication yet, `index` says nothing is published and directs the caller to `instrukt sync` in a project; `get` fails as for an unknown id.
