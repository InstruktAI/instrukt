# Build review — {slug}

Owed: independent review of the completed build, complete `review-findings`, and a verdict bound to the current reviewed commit and report digest. Record the report with `instrukt todo artifacts write {slug} review-findings '<content>'`, then `instrukt todo stamp {slug} --verdict approve --phase build_review` or `instrukt todo stamp {slug} --verdict changes_requested --phase build_review`. Review counts and the baseline are informational. Add no suite execution.

Before dispatch, read the role-attempt bindings with `instrukt todo show {slug}`. Reuse requires an active, unreleased attempt first; then observe its session with `instrukt sessions alive <id>` and send follow-ups through `instrukt sessions send <id> '<brief>'` when available. After release, use the configured `run --todo {slug}` command for a new attempt in its own runtime-created worktree at the current todo head. Use the returned path and retain earlier bindings as evidence. One outstanding workspace-role attempt permits no other role dispatch: reconcile a pending start or handoff first. Use the adapter's supported selection against the procedure's dispatch order or the global order; when selection is unsupported, report the runtime's project defaults. An unavailable active session follows recovery for that same attempt. A reply or ended turn does not establish completion.

A verdict bound to the complete report and captured todo head releases the read-only review attempt without moving a branch. Each subsequent review round starts a new attempt at the current todo head. Review rounds are counted from verdict stamps; re-evaluation alone is not a round and no admission write is required.
